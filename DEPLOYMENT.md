# LabLine Deployment Guide (Render & MongoDB Atlas)

This repository is prepared for single-origin deployment on **Render** (Web Service) connected to **MongoDB Atlas** for persistent production data storage.

> **Status Notice:** This document describes deployment configuration and manual setup steps. Code preparation has been completed; actual hosted provisioning must be performed in your Render and MongoDB Atlas dashboards.

---

## 1. MongoDB Atlas Setup

### A. Create Cluster & Database User
1. Log into [MongoDB Atlas](https://cloud.mongodb.com/).
2. Create a new database deployment selecting the **M0 Free** cluster tier (choose a cloud provider and region closest to your intended Render region, e.g., AWS / Oregon `us-west-2` or Frankfurt `eu-central-1`).
3. Under **Security > Database Access**, click **Add New Database User**:
   - Authentication Method: **Password**
   - Username: `labline_app` (or chosen identifier)
   - Password: Generate a strong alphanumeric password (store securely in a password manager; never commit to source control).
   - Database User Privileges: `Read and write to any database` (or specific `labline` database).

### B. Network Access Configuration
1. Under **Security > Network Access**, click **Add IP Address**.
2. Select **Allow Access From Anywhere** (`0.0.0.0/0`) or enter the dedicated outbound IP addresses if using a paid Render plan with static outbound IPs.
   - *Note:* Render free instances use dynamic IPs, requiring `0.0.0.0/0`. Security is enforced by strong database user credentials and TLS.
3. Save the entry.

### C. Retrieve Connection URI
1. In **Deployment > Database**, click **Connect** on your cluster.
2. Choose **Drivers** (Node.js).
3. Copy the standard connection string format:
   ```text
   mongodb+srv://<username>:<password>@<cluster-address>/labline?retryWrites=true&w=majority&appName=labline
   ```
4. Replace `<username>` and `<password>` with your database user credentials. Do not commit this URI to Git.

## 2. Render Blueprint Deployment

### A. Deploy via Blueprint
1. Log into [Render](https://dashboard.render.com/).
2. Click **New +** and select **Blueprint**.
3. Connect your GitHub repository: `https://github.com/sudo-roonakyadav/labline`.
4. Render detects the committed [`render.yaml`](./render.yaml) file.
5. In the blueprint initialization screen, give your deployment a project name.

### B. Securely Supply Environment Secrets
Under the Web Service environment variables:
- `NODE_ENV`: automatically set to `production`.
- `JWT_SECRET`: automatically generated by Render as a cryptographically random secret (`generateValue: true`).
- `MONGODB_URI`: Marked as `sync: false`. Paste your full MongoDB Atlas connection URI retrieved in Step 1C into the secret field.
- `CLIENT_ORIGIN` *(Optional)*: If left blank, the server automatically defaults to `RENDER_EXTERNAL_URL` (e.g. `https://labline.onrender.com`). Set this only if using a custom domain.

Click **Apply** to trigger the initial build and deployment.

## 3. Build & Runtime Execution

Render executes the configured workflow:
- **Build Command:** `npm ci && npm run build`
  - Installs production and build dependencies cleanly via npm workspaces.
  - Compiles the React SPA client into optimized static assets in `client/dist`.
- **Start Command:** `npm start`
  - Launches the Node.js Express server on `0.0.0.0:${PORT}`.
  - Serves API routes (`/api/*`) with strict JSON error responses.
  - In production (`NODE_ENV=production`), serves static assets from `client/dist` and routes non-API GET requests to `client/dist/index.html`.

## 4. Verification & Health Probes

Once the service deployment status transitions to **Live**, verify both endpoints:

### A. Readiness Probe (Automated Render Health Check)
```bash
curl -i https://<your-render-subdomain>.onrender.com/api/health/ready
```
- **HTTP 200 OK** when MongoDB Atlas connection is active and healthy:
  ```json
  {
    "status": "ready",
    "database": "connected",
    "timestamp": "2026-10-25T18:00:00.000Z"
  }
  ```
- **HTTP 503 Service Unavailable** if MongoDB is unreachable or credentials are misconfigured.

### B. Diagnostic Health Check
```bash
curl -i https://<your-render-subdomain>.onrender.com/api/health
```
- Returns real-time uptime, database state, and WebSocket gateway status.

## 5. Administrative Setup: Creating the First Mentor Account

Mentor privileges cannot be self-selected during registration. Public signup creates student accounts only.

To promote your administrative or mentor account:

1. Register an initial account via the public UI (`/`) using your academic email (e.g., `mentor@scaler.com`).
2. Promote the account using the CLI in one of two ways:
   - **Method 1 (Render SSH / Shell):** Open the **Shell** tab on the Render Web Service dashboard and execute:
     ```bash
     npm run promote-mentor -- mentor@scaler.com
     ```
   - **Method 2 (Local CLI connecting to Atlas):**
     ```bash
     MONGODB_URI="<your-mongodb-atlas-uri>" npm run promote-mentor -- mentor@scaler.com
     ```
3. The CLI verifies the user exists in MongoDB and updates the role to `mentor`.
4. Sign out and log back in to access the Mentor Queue Desk.

## 6. Operational Considerations (Free Tier)

- **Inactivity Sleep:** On Render's free tier, the web service automatically spins down after 15 minutes of inactivity. The first incoming request will experience a cold-start delay of approximately 30–50 seconds while the instance boots.
- **Viewing Logs:** View real-time runtime logs in the Render Dashboard under **Logs** to monitor database connection events, Socket.IO connections, and API requests.
